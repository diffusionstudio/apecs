# apecs × canvas — text flow

_Attention Is All You Need_, one entity per `Intl.Segmenter` token, laid out from scratch every
frame and drawn with the 2D context. Three spheres bounce around the window; the text has to make
room for them, and every break they force ripples down the rest of the paper.

```bash
npm install
npm run dev
```

Scroll to read. Drag either edge of the page to resize it: the columns reflow, and the column count
follows the width. The spheres stay where they are on screen while the page moves under them; grab
one to drag it, let go while moving to throw it.

## What is an entity

| On screen                   | In apecs                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------- |
| every word, space and comma | a `Token` entity: text, width, run width, style, flags — measured once                  |
| where it was drawn          | `Pos`, written by the layout system through `chunks()`, read by the draw system         |
| the three spheres           | `Ball` in screen space, plus `Shade`, an AoS trait holding the gradient                 |
| dragging one                | `Ball.held`: kinematic under the pointer, immovable in the pair loop, thrown on release |
| the page, the scroll        | `Page`, a world trait: the width is the input, everything else is output                |
| the frame                   | a `Schedule`: `spheres` → `layout` → `draw`                                             |

The paper is 11,591 tokens. The layout walks all of them every frame — there is no incremental
path, no dirty tracking, no cached line — in about a millisecond. The draw culls to what is inside
the viewport: 500 to 1,400 `fillText` calls depending on the column count, one to two milliseconds
at a device pixel ratio of 2. The numbers are in the card at the bottom left.

## The layout

`src/layout.ts` is one pass in document order over the token columns. The state is a handful of
scalars at module scope: the cursor, the open line, the open segment, the column, the sheet.

- **Runs, not words, are what fit.** `Intl.Segmenter` splits `self-attention,` into five segments.
  A token becomes a `HEAD` when a line may break before it (after a space, a hyphen, a slash), and
  `buildDocument` stores on each head the width of everything glued to it. The fit test is one
  compare against the run width; no lookahead in the kernel.
- **A sphere is a chord.** For a line's band `[y, y + lh]` the sphere overlapping it cuts out its
  widest chord inside the band. The cuts are merged and their complement, minus anything narrower
  than a couple of ems, is the list of segments the line's words may go in. A line with no segment
  is skipped, not filled.
- **A run that fits nowhere on a line moves to the next line, and so on, until a line is clear.**
  On a clear line it is placed whether it fits or not, so the walk always terminates and a word
  wider than the column overflows once instead of looping.
- **Justification is a fix-up over the segment just closed**, scaling each space by the same ratio.
  A segment that would have to stretch its spaces past 2.5× stays ragged, which is what keeps the
  short lines beside a sphere from turning into rivers.
- **Centred lines are anchored, not filled.** A title is laid out centred as if nothing were in the
  way; a sphere then moves only the runs it touches, splitting the line at the run boundary that
  displaces the fewest tokens and wrapping only when neither side has room. A sphere in the margin
  leaves a centred line exactly where it was.
- **Sheets, not one long page.** The page is a stack of √2 sheets. Columns fill a sheet top to
  bottom and left to right; the front matter spans the whole content width and the columns begin
  under it. The gap between sheets is where a column break lands.

## One page, one chunk

The world is created with `pageSize: 1 << 15`, larger than the paper, so every token is in a
single page and the layout reads one chunk whose rows are in spawn order. That is what makes the
justification fix-up a plain backward loop over `X[]`. It is a deliberate constant, not a
limitation of the library, and `buildDocument` asserts it in dev.

## Layout of the source

- `src/traits.ts` — every trait and flag. Read this first.
- `src/paper.ts` — the paper as a list of blocks, generated by `scripts/paper.py` from the
  [arXiv HTML](https://arxiv.org/html/1706.03762v7). Text only: figures and tables are dropped,
  math is flattened to spans with sub- and superscripts, footnotes follow the paragraph that cites
  them.
- `src/styles.ts` — sizes, line heights, alignment per kind; one font string per (kind, face).
- `src/document.ts` — segmenting, measuring, `spawnMany`, the run widths.
- `src/layout.ts` — the system described above.
- `src/spheres.ts` — the colliders: walls, elastic pairs by area.
- `src/draw.ts` — sheets with an offset-free shadow, culled text, the spheres.
- `src/main.ts` — the world, input, the loop.

The paper is by Vaswani et al. (2017) and is reproduced here under the arXiv non-exclusive
distribution licence for the purpose of this demo.
